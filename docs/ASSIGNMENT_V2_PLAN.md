## 2. 老師發布作業流程

一份作業是容器，可以依序加入一個或多個活動：

1. 聽力：選教材、頁碼或 Unit、音檔，以及每檔 1～10 次有效聆聽。
2. AI 選擇題：選教材與頁碼範圍，預覽並核准題組，再把固定題目快照發布給全班。
3. 發音練習：選教材與頁碼範圍，核對句子，設定完成方式與最多評分次數。
4. 混合作業：可同時包含以上三種活動，全部必做項目達標後才算整份完成。

老師必須看到發布前摘要，包括班級、截止日、活動順序、教材、頁碼、題數、發音句數及完成條件。發布後使用不可變快照；後來修改教材來源不應改寫既有作業。

## 3. AI 題組規則

- AI 題組由老師建立一次並審核，全班學生作答同一份快照，不替每位學生重複生成。
- 題目只能根據已發布且由老師核准的 `source_text`／逐字稿建立。
- 只有頁碼、沒有核准文字來源時，後端必須拒絕生成，不得猜測「Workbook 2 P22」的內容。
- 學生重做只新增作答紀錄，不重新呼叫生成服務，也不消耗學生個人的 AI 生成額度。
- 題組可設定及格分數，預設 80 分；作業完成獎勵仍以整份作業一次性發放，不因重做無限發獎。

## 4. 發音練習規則

- 每個提示句預設採「完成一次有效評分」即可完成，也可由老師設定目標分數。
- 每句最多 3 次計分，資料庫允許老師在 1～5 次內設定。
- 保存整體、準確度、流暢度、完整度及韻律分數；不保存學生的原始錄音檔。
- 每次請求必須有唯一 `attempt_key`，避免重送造成重複計次。
- 發音項目完成後才更新該項進度；整份作業全部必做項目完成後才發一次作業獎勵。

## 5. 相容與安全

- 舊版聽力作業保持 `schema_version = 1`，現有畫面與紀錄不轉換、不刪除。
- 新混合作業使用 `source_type = multi_activity_v2` 與 `schema_version = 2`。
- `assignment_v2` 先只對指定學生開啟；未開啟者只走舊流程。
- 新資料表啟用 RLS，前端 `anon`／`authenticated` 不直接讀寫；只能由驗證 Firebase ID Token 並重新核對角色、班級與 enrollment 的 Edge Function 處理。
- 老師只能發布授權班級，管理員可處理全部班級；教材購買者、試用者及離校生不能讀取新班級作業。
- 原始錄音、Secret、家長資料與學生密碼不得寫入作業快照或錯誤紀錄。

## 6. 分階段上線

1. 第一階段：additive schema、方案 feature、獨立發音權限、AI 月額度與契約測試。
2. 第二階段：教師混合作業編輯器、教材頁來源管理、`assignment-manager` V2 寫入與預覽。（本機完成；學生端尚未啟用）
3. 第三階段：學生作業播放器、AI 作答、發音評分、逐項進度與一次性完成獎勵。（AI 題組讀取／伺服器快照評分／活動進度本機完成；其餘項目未開始）
4. 第四階段：指定在校帳號開啟 `assignment_v2`，驗證權限隔離、重做、截止時間、冪等與手機版。
5. 第五階段：完成正式 Stripe NT$299 AI Price 同批切換後，再分批開放其他在校生。

## 7. 驗收重點

- 在校生可直接進入 AI 教材與發音教練；其他學生需要有效基本方案加 AI 加購。
- 教材包 90 天與基本會員可聽全部正式音檔，但都看不到新作業。
- 同份混合作業的三種活動可正確排序、完成與保存進度。
- 一般教材頁與作業頁的有效聆聽使用同一套 80% 後端驗證，不重複計次或發獎。
- 學生不能修改題目快照、偽造分數、班級、學生 ID 或完成狀態。
- 412px 手機、平板、桌面、Sidebar、MusicPlayer、麥克風權限與 iPhone safe area 均無遮擋。
