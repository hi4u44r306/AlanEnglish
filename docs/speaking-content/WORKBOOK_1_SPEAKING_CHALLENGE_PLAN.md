## 1. 目標

依 Workbook 1 學生版與教師版逐頁審閱結果，完成所有適合國小學生的口說大挑戰關卡。每一關必須有明確教材來源、兒童友善的互動、後端權威答案、管理員草稿核准流程、循序解鎖及可驗證的發布紀錄。

本計畫不把每一頁機械式轉成一關；同一學習目標的頁面會合併成約 6 至 12 題的小關卡。學生介面顯示主題名稱及「配合第 X 頁」，內部 template key 維持穩定，已發布版本不可就地覆寫。

## 4. 永久建立規則

1. 只使用已核准的教材頁面、圖片、題目與答案，不依 OCR 或 AI 猜測正式答案。
2. 新內容一律先建立 `draft`；管理員逐題預覽、修正並明確核准後才能發布。
3. 已發布題組不可就地改寫；修正時建立新版本並保留舊版本及回復依據。
4. 前端只傳 `question_id` 與學生作答；後端從已發布版本取得參考答案並重新驗證身分、教材 entitlement、題組狀態與順序。
5. 圖片及音檔保持私人；學生只取得短效 signed URL，不取得 R2 object key。
6. 示範音檔只在管理員發布／補產生時生成一次；相同文字、聲線與設定雜湊必須重用，不讓學生觸發付費生成。
7. 原始學生錄音只暫存在瀏覽器；只保存評分、辨識文字與必要逐字結果。
8. 個人回答使用結構化欄位，不把姓名、年齡或電話號碼寫入公開標準答案；電話題只能使用教材或虛構號碼。
9. 歌曲頁在授權未確認前不得匯入完整歌詞、生成逐句朗讀或發布歌曲關卡。
10. 每題先給一項最重要的改善提示；兒童容錯不得把辨識服務常見轉寫誤差直接當成發音錯誤。

## 7. 每一批固定工作流程

1. `git fetch origin`、列出 Worktree、確認唯一 Writer branch 與 clean status。
2. 唯讀盤點目前題組／template／版本／題數，保存 preflight 證據。
3. 核對學生版、教師版及圖片來源，完成題目、答案、accepted responses、alt text 與頁碼清單。
4. 建立或沿用 idempotent 草稿；不得直接發布。
5. 管理員逐題預覽、修改與核准。
6. 發布後才生成或重用示範音檔；確認私人 R2、signed URL 及成本 ledger。
7. 學生帳號驗收題序、循序解鎖、錄音、容錯、失敗提示、完成與實際獎勵。
8. 老師／管理員驗收全關可預覽且不寫入學生進度／獎勵。
9. 執行 targeted React tests、相關 contracts／Edge syntax、`npm run build`、`git diff --check` 與 Secret／P0／P1 review。
10. 更新 `docs/PROJECT_STATUS.md` 與 `docs/網站使用手冊.md`，建立乾淨 commit、push feature/integration branch，驗證 local HEAD 等於 remote HEAD。
11. 只有需要 migration、正式 Edge Function、正式資料或正式部署時，依風險閘門取得該批授權並做 postflight；前端部署不得覆蓋或移除既有 Speaking 功能。

## 8. Git 與發布護欄

- 不在 `main` 直接開發，不從舊 Worktree 加入 unrelated 功能。
- 本計畫優先沿用 `integration/workbook1-speaking-recovery`，除非其已完成且另有明確新 branch 決策。
- 禁止 force push、刪除 integration branch、修改已部署 migration、刪除正式題組或學生進度。
- 部署前比較功能 branch、最新 `main` 與正式 bundle，確認 A-Z、P14 至 P17、P21／P22 框架、導航及評分後端都仍存在。
- 若 Worktree 超過 5 個，先做 cleanup audit，不建立新 Worktree。
